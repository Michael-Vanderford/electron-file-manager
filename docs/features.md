**Status:** `Verified` means the named automated scenarios pass; `Partial` means only some behavior is tested; `Untested` means implementation exists but no relevant automated verification was identified. No manual feature certification has been performed for this baseline. Read the audit before treating a feature as complete.

Development regenerates the three static preload bundles at startup; `npm run build` and `npm run build:win` generate them in prebuild hooks. Generated files are ignored by Git and must be included when packaging. No runtime eval or additional bundler dependency is used. Main-process path operations remain validated synchronous IPC because sandbox preloads cannot load Node's path module. CSP retains inline **styles** for existing layout behavior, while inline scripts, frames, objects, remote connections, and form submissions are disallowed.

Linux Open With now uses the registered Desktop Entry ID through `xdg-mime` and `gtk-launch`, preserving the existing default-association update and delegating Desktop Entry field codes to GTK. These tools are runtime prerequisites for that action; failures are reported rather than running an arbitrary launcher command string. The configured disk utility accepts a quoted executable and literal arguments; shell expansion, pipelines and redirection are no longer evaluated. Production launch scripts and decoder defaults no longer pass --no-sandbox; an explicit caller opt-out is forwarded to the decoder for restricted test environments.

## Repeatable checks

```sh
npm run test:regression
# Linux without a usable display:
xvfb-run -a npm run test:regression
```

The regression command runs all configured Jest suites, then the full Electron Playwright suite, stopping on failure. Profiles and file-operation fixtures live in temporary directories. Build artifacts under `dist/` are excluded from Jest discovery so a packaged `.snap` file is not mistaken for an obsolete Jest snapshot. The existing excluded autocomplete suite stays excluded; this command is not a promise to cover every feature above.

For development, `npm run test:unit` and `npm run test:e2e -- --grep 'test name'` run smaller checks. Record exactly which command passed; do not equate focused checks with the full regression run.

## Baseline validation

Before adding these documents, all 15 configured unit suites passed: 86 tests. Native GIO emitted proxy warnings in the restricted environment; those checks still passed. `xvfb-run -a npm run test:regression` passed: **86 unit tests across 15 suites and all 20 Electron Playwright tests** (2026-10-29). No real disconnected network mount, packaged build, Windows run, or manual accessibility validation is included.

Device behavior update: inaccessible mounts are intentionally hidden at the user’s request. Discovery failure no longer republishes unverified cached mounts. Capacity/accessibility probes remain isolated with the existing parent deadline; GIO commands also have a 2.5-second command deadline. No real mounts were modified for testing.

Virtual-scroll regression: repeated wheel input in a 7,000-SVG directory reproduced continuous idle scrolling before the fix (over 10,000 pixels of movement in the sampled idle frames). Disabling browser scroll anchoring within `.virtual_view` prevents spacer replacement from causing additional scroll events. Playwright samples idle animation frames after five wheel gestures in both grid and list views and checks that scrolling stops.

USB hot-plug update: scans now publish complete verified lists rather than partial prefixes. Mounted volumes and unmounted drives are merged, and device entries are reconciled by identity so unchanged controls are preserved. Monitor events trigger debounced discovery and one delayed retry; events received during discovery request a follow-up scan instead of being dropped.

Search responsiveness update: results are delivered in acknowledged batches of up to 256 files, large results reuse virtual rows within the search scroll container, and completion renders the final result set. Search cancellation is attached to close, directory navigation, and tab removal; unique IDs prevent reused-panel collisions. Directory data remains separate from matches so closing search restores the folder. Current checks cover 7,001 actual matches; this is functional coverage rather than a measured performance guarantee for every dataset.

Search option semantics verified with temporary fixtures: sizes are bytes; minimum/maximum and modified-from/to bounds include exact matches. Depth counts the search root as level 0, so the default 1 includes files in direct child directories; an empty depth field leaves recursion unrestricted. Datetime-local inputs are converted using the browser timezone. Reversed size/date ranges show validation messages without launching the search.

Dashboard GVFS update: dashboard probes reuse `mount_info` for GIO filesystem capacity, device charts retain their discovered name and navigation path, and failed queries no longer render an Unknown chart. Worker and simulated-IPC Electron checks cover these paths; no real network mount was contacted or manually verified.

P0 implementation (2026-10-30): FILE-02/03/05/06/09 now use link-aware planning and safe staged replacement where overwriting is explicitly requested. Normal copies preserve verbatim symlink text and reject unapproved late collisions. Source trees are never traversed through selected/nested symlinks; copy/move destinations are checked through existing parent aliases, and descendant operations recheck parent links. Deletion treats selected links as leaf entries and propagates boolean removal failure.

Replacement behavior: content/link snapshots verify overwrite copies before commit; move sources are cleaned only after commit and only while expected entries remain unchanged, with non-recursive directory cleanup preserving newly arrived files. A sibling workspace retains the original during replacement, a per-destination lock prevents overlapping app replacements, and private profile journals record recovery paths before the original moves. On restart, an absent destination is restored from its backup. If both a destination and an uncommitted backup exist, both are retained and the app reports the recovery path instead of guessing. Compression now creates output exclusively in the same staging mechanism, offers existing overwrite/keep/skip choices for collisions, rejects output overlapping any selected input, and closes streams/workers/progress on success, error, and cancellation. Conflict actions are keyboard-focusable buttons.

P0 limitations: directory replacement has a brief rename gap and is not claimed universally atomic. File publication requires destination-filesystem hard-link support; unsupported publication fails with the original preserved rather than using an unsafe overwrite fallback. Journals cover process interruption, not power-loss durability. An interruption before the first journal record can leave an orphan lock; subsequent attempts report its path for inspection rather than breaking an unknown lock. Uncooperative external writers and adversarial path swaps cannot be made fully transactional with portable Node path APIs. New source content detected after commit is retained, potentially alongside a completed destination. No real network mounts, Windows symlink permissions, or packaged builds were certified. Extraction and the existing XZ codec finding remain outside this P0 change.

P0 grouped-virtual coverage uses a synthetic click on the row itself before invoking Copy/Delete; ordinary grid flows use physical pointer/keyboard actions. An additional isolated check exposed existing grouped-virtual keyboard selection that highlights a card but leaves command selection empty; this is tracked separately as TODO R31, not silently fixed or claimed covered by the P0 transfer regression.
