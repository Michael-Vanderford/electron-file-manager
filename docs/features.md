Development regenerates the three static preload bundles at startup; `npm run build` and `npm run build:win` generate them in prebuild hooks. Generated files are ignored by Git and must be included when packaging. No runtime eval or additional bundler dependency is used. Main-process path operations remain validated synchronous IPC because sandbox preloads cannot load Node's path module. CSP retains inline **styles** for existing layout behavior, while inline scripts, frames, objects, remote connections, and form submissions are disallowed.

Linux Open With now uses the registered Desktop Entry ID through `xdg-mime` and `gtk-launch`, preserving the existing default-association update and delegating Desktop Entry field codes to GTK. These tools are runtime prerequisites for that action; failures are reported rather than running an arbitrary launcher command string. The configured disk utility accepts a quoted executable and literal arguments; shell expansion, pipelines and redirection are no longer evaluated. Development launch scripts (`npm start` and `npm run start:clean`) explicitly pass `--no-sandbox` at the user’s request to avoid Linux SUID helper setup after Electron updates (PLATFORM-01/SEC-03). This disables Chromium OS sandboxing for those launches; renderer isolation and IPC restrictions remain configured. Packaged launch arguments and decoder defaults are unchanged; an explicit caller opt-out is forwarded to the decoder. Launch-script arguments are statically verified; desktop startup is not re-certified by that check.

## Repeatable checks

```sh
npm run test:regression
# Linux without a usable display:
xvfb-run -a npm run test:regression
```

The regression command runs all configured Jest suites, then the full Electron Playwright suite, stopping on failure. Profiles and file-operation fixtures live in temporary directories. Build artifacts under `dist/` are excluded from Jest discovery so a packaged `.snap` file is not mistaken for an obsolete Jest snapshot. The existing excluded autocomplete suite stays excluded; this command is not a promise to cover every feature above.

For development, `npm run test:unit` and `npm run test:e2e -- --grep 'test name'` run smaller checks. Record exactly which command passed; do not equate focused checks with the full regression run.

### Bounded probes and native watchers

Location validation and directory-write permission checks run through timed, coalesced subprocesses; a closed initiating window cannot continue a pending permission-gated job. Footer `stats` uses the same accessibility/GVFS-aware capacity query as Dashboard, with strict failure semantics instead of zero-valued error fallbacks. Ordinary disk queries stop at four live children per manager instance; validation/write/metadata queries can use reserved capacity up to eight. Stuck children remain counted until exit. `close`, after IPC drain, determines a missing reply so a buffered successful reply is not discarded at `exit`. These are per-instance bounds, not an application-wide process scheduler. Other synchronous main-process metadata and transfer-preparation operations remain R23 work.

Watchers have no unmatched-event global-window fallback. Asynchronous native event classification avoids duplicate synchronous metadata reads; full metadata uses bounded subprocesses. Revisions and subscription identities reject results superseded by deletion/navigation. Created and modified items carry their directory through existing file metadata, and deletion replies carry explicit source-directory identity. Directory disappearance and watch failures are surfaced. Paths are normalized before registration, fixing trailing-slash mismatches from autocomplete. Existing-tab switches now rebind the active window's watcher and invalidate old listing requests; non-directory special tabs release their subscriptions. Window close releases subscriptions and pending callbacks cannot target its replacement.
